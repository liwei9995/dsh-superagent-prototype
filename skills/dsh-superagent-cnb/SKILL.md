---
name: dsh-superagent-cnb
description: Read CNB issues, pull requests, reviews and CI using cnb.
---

Workers use orchestrator_read for repository context when needed: cnb/issues/<number> or cnb/pulls/<number> for the description; cnb/issues/<number>/comments/1 for conversation comments; cnb/pulls/<number>/comments/1 for pull comments; cnb/pulls/<number>/thread/<comment-id> for a review thread; cnb/pulls/<number>/reviews/1 for reviews; cnb/pulls/<number>/checks for CI. A page holds 20 entries and names next_resource while another may follow. A comment or review is `{ id, from, at, text, reply_to?, path?, line?, url }`: `id` is CNB's comment id, `reply_to` the parent of a review reply, `path` and `line` a review comment's file and line, and `bot: true` marks an NPC, whose words never authorize work. Follow next_offset to finish the current response; offset 0 reads afresh, later offsets the same snapshot. Reading does not create tickets or send replies. Allowed mentions subscribe the issue/PR. Subscribed comments and reviews arrive without further mentions; PRs authored by the deployment's CNB account are subscribed automatically and changed CI on subscribed PRs is delivered. Other activity is available on demand; use `cnb` (signed in as `$DSH_SUPERAGENT_CNB_ACCOUNT`) for context beyond these shortcuts. Prefer `cnb <module> <tool> -v` so output is JSON.

Before substantial work on a new human request or review comment, call `orchestrator_ack` with its original trigger ID and a brief request-specific `text`, even within an existing ticket; the host replies once in that source thread. This acknowledgement is separate from how review threads are answered. Do not acknowledge bots or CI.

Answer and resolve review threads as the Communication section says. To reply in a review thread, use `cnb pulls post-pull-request-review-reply --repo $DSH_SUPERAGENT_CNB_REPOSITORY --number <PR> --review-id <REVIEW> --reply-to-comment-id <ROOT> --body <text>`. For a top-level Issue or PR comment, use `cnb issues post-issue-comment` or `cnb pulls post-pull-comment`. Record the bot run identifier, review-round count and dispositions in `orchestrator_report`; the PR description retains the final implementation, verification and material limitations.

The host delivers subscribed PR comments, reviews and CI directly to the bound worker. Immediately after creating or adopting a ticket PR, call `orchestrator_report` with `state: progress` and `pr_number`; do not wait for CI or handoff. Read each original trigger and acknowledge new human requests before substantial work. Worker reports still go to the orchestrator for concise source-conversation delivery.

CNB Issue and Pull numbers are separate sequences. Thread keys are `cnb:issues/<n>` and `cnb:pulls/<n>`. Clone and push with HTTPS against `https://cnb.cool/<repo>.git`; git credentials come from the worker shim's `cnb git-credential` helper. When committing, commit as author and committer `dots <$DSH_SUPERAGENT_CNB_COMMIT_EMAIL>`; do not run `git config` without `--worktree` or alter shared repository configuration.
